# Sustain 1.1.2 corrective bootstrap

Public 1.1.1/build 4 contains Sparkle but cannot start it. Its
`DeveloperIDSignatureInspector` calls `SecCodeCopySigningInformation` without
`kSecCSSigningInformation`, so the certificate array is absent and the app
hides **Check for Updates…**. On an Apple silicon Mac running macOS 26.6.2,
the installed public 1.1.1 app reproduced the missing command. A direct
Security API check against that same signed app returned no certificates with
empty flags and a valid Developer ID Application leaf with the signing flag.

1.1.2/build 5 is based on the public `v1.1.1` tag and changes the Security API
flag without changing the library format or user-facing features. Users of
1.1.1 need one manual DMG install. After that, the 1.1.2 → 2.0 Sparkle path
must be tested from `/Applications` before 2.0 publication.
